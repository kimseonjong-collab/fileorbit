# FileOrbit V0.4 Acceptance

## Release gate
V0.4 is acceptable for a Windows checkpoint build only when all items below pass.

### Folder Doctor / Folder Map
- [x] Existing work root is selected explicitly by the user. (desktop folder dialog; Work Root is separate from Downloads Root)
- [x] Folder scan is read-only. (backend scan path performs metadata/read traversal only; no mutation calls)
- [x] Noise exclusions do not mutate disk content. (excluded directories are skipped by WalkDir filter only)
- [x] Folder Map is persisted only after explicit approval. (`fileorbit-folder-map-v1` is written by the explicit approval action)
- [x] Drift between saved Folder Map sources and a later scan is visible. (saved/current source sets show added/missing counts)

### Downloads Organizer
- [x] Downloads root is selected explicitly. (desktop UI keeps Downloads selection separate from Folder Map work root)
- [x] Scanning does not move, rename, delete, or overwrite files. (`scan_downloads` reads directory entries/metadata only)
- [x] Recommendation, review, and hold states are distinguishable. (separate counts, filters, status labels, and confidence treatment)
- [x] Manual classification correction is stored locally. (role overrides + learned filename tokens persist locally and are scoped to the approved map)
- [x] Per-file review decisions and overrides are scoped to Folder Map root + Downloads root. (V0.4 scoped local persistence; empty/unapproved scopes are not persisted)
- [x] Re-scan retains decisions only for files still present. (scan reconciliation prunes stale decision/override keys)

### Move safety
- [x] Move requires approved Folder Map. (UI gate + backend approved-root validation)
- [x] Move requires explicit per-file approval and final Move confirmation. (desktop Move Gate)
- [x] Rust validates source under selected Downloads root. (preflight + execution-time canonical-path guard)
- [x] Rust validates target under approved work root. (preflight + execution-time approved-root containment, including canonical target-parent guard)
- [x] Parent-directory traversal and invalid relative path elements are rejected. (backend guard + Rust unit test)
- [x] Existing destination collision is rejected; overwrite is never silent. (move primitive guard + Rust unit test)
- [x] Same-volume move is journaled. (`planned` then `moved`/`failed` entries are appended around execution)
- [x] Cross-volume fallback uses temporary copy + byte-size verification before source removal. (forced fallback Rust unit test)
- [x] Failed cross-volume source removal attempts rollback of the created destination. (fallback implementation removes created target if source removal fails; controlled failure injection remains optional)

### Journal / Undo
- [x] Planned, moved, failed, undone, and undo_failed states are auditable in the JSONL journal; execution-time Move failures are journaled after `planned`.
- [x] Move history is persisted in the app-data JSONL journal and reloaded after restart.
- [x] Undo availability is derived from the latest successful moved/undone state per source.
- [x] Undo collision stops that item rather than overwriting the original path. (undo precheck Rust unit test)
- [x] Failed Undo remains retryable after the external cause is resolved.
- [x] Transaction detail exposes source, target, status, and error.

### Build / regression
- [x] Frontend build passes. (CI run 36097417620, 2026-09-25)
- [x] Rust/Tauri CI including cargo test passes. (run 36097417620)
- [x] Web Preview build passes. (run 36097417609)
- [x] Web Preview clearly states that it uses demo data.
- [x] Desktop safety copy describes V0.4 explicit Safe Move/Undo, not V0.1 read-only behavior.
- [x] Windows installer is generated only at an explicit checkpoint request.
- [x] Windows release is built as a GUI subsystem app; no console window is requested by the release binary.

## Explicitly out of scope
Background file movement, scheduled file movement, automatic deletion, cloud file-content upload, and silent overwrite are not part of V0.4.
