## Pass/fail rule
PASS requires the expected GUI result and no unexpected filesystem mutation. Any crash, silent overwrite, unexpected move, stale approval reuse, missing audit state, or persistence loss is FAIL. Stop the stable-release path on the first FAIL.

## Sequence
1. **V0.4 Folder Map compatibility** — Open RC2 from an existing disposable V0.4-approved Folder Map state. PASS: approved root/targets restore unchanged.
2. **Read-only before final Move** — Scan disposable Downloads without final confirmation. PASS: no filesystem mutation; Move requires per-file approval, backend validation, and final confirmation.
3. **Normal Move + History** — Move one approved synthetic file. PASS: exactly one approved move, no overwrite, correct History counts.
4. **Undo + refresh** — Undo it. PASS: source restored, target gone, History/Downloads refreshed, old validation/final-arm unusable.
5. **Duplicate destination** — Create two synthetic files resolving to one target. PASS: conflict isolated and excluded from effective Move set.
6. **Windows-invalid destination** — Create a synthetic invalid-target classification. PASS: invalid row isolated and cannot be approved/moved; no silent rename.
7. **Journal export** — Export to a new disposable destination. PASS: strict-readable copy, no overwrite, live journal unchanged.
8. **Full restart** — Exit the app completely and relaunch RC2. PASS: Folder Map and Move/Undo history restore consistently; stale Move readiness does not.

## Stable-release decision
V0.5 stable remains **BLOCKED** until all eight items are recorded PASS against the frozen RC2 installed binary. CI/backend tests are supporting evidence only.

After all eight PASS, record Windows version, installer type (EXE/MSI), RC2 file hash, completion time, and the eight results before authorizing stable.
