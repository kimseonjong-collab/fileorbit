# FileOrbit V0.5 Development Baseline

V0.4.0 is the immutable stable safety baseline. V0.5 work must preserve its read-only-first, explicit-approval, no-delete, no-overwrite, journaled Move/Undo contract unless a future acceptance document explicitly changes that contract.

## First V0.5 tranche

- [x] History diagnostics: make interrupted/planned-only transactions and journal growth state easier to understand without changing files.
- [x] Review ergonomics: improve explanation of why a download is Recommended / Review / Hold and what user action changes the outcome.
- [x] Folder Map diagnostics: surface ambiguous roles and multi-source roles before Downloads routing.
- [ ] Journal maintenance design: define an explicit export/archive mechanism before any compaction feature. No automatic deletion or compaction.
- [ ] Performance guardrails: retain single-pass History aggregation and transaction-scoped journal validation; add measurable regression gates before optimization changes.
- [x] Stable compatibility: V0.4 journal records and saved Folder Map data remain readable by V0.5.

## Out of scope until separately approved

- Automatic/background file moves
- File deletion
- Silent overwrite or conflict replacement
- Automatic journal deletion/compaction
- Cloud upload/sync
- Moving files outside the approved Folder Map

## Implemented baseline

- History labels planned-only records as incomplete/review-required instead of implying a completed failure state.
- Downloads explains Recommended / Review / Hold actions and warns when approved Folder Map roles have multiple source folders, so automatic routing stays fail-closed.
- Rust regression coverage loads a V0.4-shaped JSONL journal record to protect backward readability.
